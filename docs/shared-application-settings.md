# 작업 공간 공통 앱 설정

현재 영속 저장은 [SQLite v2](sqlite-storage.md)다. 아래의 공통 설정·명령 영수증·복구 순서는 같은 Store API와 SQLite 트랜잭션을 통해 유지된다. 자체 저널에 관한 과거 설명은 v1 이전 입력에 적용한다.

2026-10-20 사용자 요청에 따라 LLM 연결·일반 설정과 에이전트·도구/MCP·스킬 구성의 소유권을 작업 공간에서 앱 프로필로 옮겼다. 기존 작업·대화·실행의 소유권을 합치는 변경은 아니다. [작업 규칙](../AGENTS.md)에 따라 기존 ID·참조·CAS·읽기 전용·비밀 저장 경계를 유지한다.

## 사용 방법

1. 작업 공간을 새 버전으로 연다. 최초 이전 시 앱의 최근 사용 기록에 있는 공간에서도 모델을 읽기 전용으로 가져온다. 현재 공간의 일반 설정·에이전트·도구/MCP·스킬도 공통 보관소로 이전한다.
2. 모델을 처음 등록한다면 기존과 같이 API 키 저장 → 모델 설정 저장 → 기본 모델 지정을 한 번 진행한다.
3. 다른 작업 공간을 열거나 새로 만들어도 같은 모델 목록·기본 모델·일반 설정·에이전트 구성·도구·스킬을 사용한다. 앱을 종료했다가 다시 실행해도 유지한다.
4. 다른 공간에서 공통 구성을 변경하면 이후 여는 공간에도 적용한다. 공통 구성을 삭제하면 옛 작업 공간의 자동 이전으로 되살아나지 않는다. 명시적으로 다시 만든 항목은 사용할 수 있다.

모델은 최초 이전 때 앱의 `recent-workspaces.json`에 기록된 기존 공간에서도 가져온다. 임의의 사용자 폴더를 검색하지 않는다. 최근 기록 밖의 공간은 직접 열어 이전할 수 있다. 공통 기본 모델이 이미 있으면 그대로 유지하고, 없으면 최근 기록 순서의 기존 기본값을 적용한다. 서로 다른 ID의 모델은 같은 이름이어도 별도 항목으로 보존하고, 이름 중복이 있으면 가져온 표시 이름에 `(1)`, `(2)`처럼 구분자를 붙인다. 원래 이름은 이전 보관 기록에 유지한다. API 키는 기존 참조를 사용한다.

| 기존 앱 프로필의 창·테마·최근 공간 환경 설정 | 회사·사이트·작업 템플릿·분류·작업 데이터와 그 귀속 |

**Bypass는 이전에 합의한 현재 작업 공간 범위를 유지한다.** 한 공간의 도구 승인 생략 설정이 다른 공간에 승인 권한을 부여하지 않는다. 화면에서도 적용 범위를 표시한다. 모델·일반 설정의 공유가 기존 작업 공간의 명시적인 모델 선택을 임의로 해제하지 않는다.

설정 편집은 기존과 같이 쓰기 가능한 작업 공간을 연 상태에서 진행한다. 공간을 열기 전의 독립 설정 화면이나 읽기 전용 공간에서의 공통 설정 편집은 이번 변경에 포함하지 않는다.

공통 일반/정책 설정의 실제 저장 키는 `rpc/src/shared_settings.rs::common_key`의 30개다. 기존 일반/재시도 22개와 `intercept_enabled_tools`·`llm_judge_*` 7개를 포함한다. `brave_key_set`·`tavily_key_set`은 키 저장 여부를 보여 주는 파생 표시이며 독립 설정으로 복사하지 않는다. 새 설정을 추가할 때 공통 환경 설정인지 작업 공간의 실행 상태인지 먼저 분류한다.

## 저장·이전·복구 계약

- `main.rs`가 OS 앱 경로 API 또는 사용자가 지정한 앱 프로필을 결정한다. `NativeApp`은 `Service::spawn_with_profile`로 동일 프로필을 전달한다. 공통 저장소는 `<앱 프로필>/shared-settings`에 있다. 개발 PC의 절대 경로를 제품 코드에 넣지 않는다.
- 공통 저장소도 기존 `Store`의 OS 단일 writer 잠금·CAS·명령 영수증·저널을 사용한다. 별도 DB·서버·새 의존성은 추가하지 않는다. 독립 임베디드 호출자는 `Service::spawn`으로 격리 실행할 수 있다. 제품 UI와 실행 파일 통합 자체 시험은 프로필을 명시한다.
- 카탈로그 형식은 `format_version=1`이다. 원래 작업 공간 저장 형식과 업무 입력은 유지한다. 검증에서 발견한 `ui.deleteMcpServer` 결과의 누락된 ID 변환은 생성기·양쪽 계약·검증기에 반영해 기존 반환값을 정상 수락하도록 수정했다. 기존 FK가 모델 ID를 참조하므로 공간에는 같은 ID를 가진 모델·설정의 투영을 유지한다. 공통 카탈로그가 진본이다.
- 카탈로그 JSON은 검증된 불변 Blob에 저장하고 설정 행에는 버전과 BlobRef만 둔다. 과거 인라인 v1 카탈로그도 읽어 다음 저장에 이전한다. 현재/이전 프롬프트와 카탈로그의 실제 BlobRef는 같은 내부 명령 영수증의 `normalized_params`에 기록해 무결성 검사와 GC가 추적한다. 큰 결과를 다시 Blob로 만드는 기존 Store 동작에도 참조가 숨지 않는다. 도구 스크립트와 충돌 보관본이 커졌다는 이유로 원본을 잘라내지 않는다.
- 확장 카탈로그의 `configuration`·삭제 목록은 기본값이 있는 필드로 추가해 앞선 모델/일반 설정 전용 카탈로그도 읽는다. 에이전트/도구는 key, MCP는 name을 공통 식별자로 사용한다. 공간에 이미 있는 내부 ID는 유지하고 새 항목에만 해당 공간의 ID를 발급한다. 이름이 같은 기존 구성의 충돌은 공통 값을 유지하며 이전 원본을 카탈로그에 보존한다.
- 현재 프롬프트가 달라지면 목적지 공간의 버전 순서에 새 버전을 추가한다. 과거 버전의 ID·본문을 다른 공간의 이력으로 교체하지 않는다. 64KiB를 넘는 프롬프트도 BlobRef를 유지하며 SHA·길이를 확인한 바이트를 공통 저장소와 쓰기 가능한 목적지에 복사한다. 읽기 전용 공간의 현재 공통 프롬프트 조회/내보내기는 공통 Blob에서 읽을 수 있다. 사용자 도구의 임의 JSON을 Body로 추측하지 않는다.
- 트리거의 공통 ID와 공간 ID를 별도 별칭으로 연결하고 동일한 트리거도 일대일로 대응한다. `last_fire`·실행 기록은 공유하지 않는다. 정확한 MCP 도구별 거부 규칙을 보존하며 연결 정의가 바뀐 서버의 로컬 도구 캐시만 무효화한다. 저장·열기 과정에서 외부 MCP 검색이나 에이전트 실행을 시작하지 않는다.
- 알림 채널·전역 승인 규칙은 기존 native ID로 공통화한다. 동순위 승인 규칙의 평가 순서를 보존하기 위해 신규 투영의 원래 생성 시각을 기존 `Store::commit_import`로 이전한다. 읽기 전용 투영도 같은 시각을 쓴다. LLM 모델 삭제는 직렬화된 심사 모델 바인딩을 동일 CAS에서 해제한다. 이 작업으로 알림 전송·기존 승인 재시도를 실행하지 않는다.
- 공통 구성이 만들어진 후에는 공간을 열 때 기본 구성을 다시 심지 않는다. 삭제한 기본 MCP나 변경한 프롬프트의 부활 및 불필요한 저장 세대 증가를 막는다. 향후 기본 구성 변경은 앱 프로필의 명시적 이전으로 처리해야 하며, 공간별 자동 재시딩으로 대체하지 않는다.
- 처음 보거나 복원된 공간에서 새 모델 ID·아직 없는 설정 키를 발견하면 가져온다. 이미 있는 공통 값을 오래된 공간의 값으로 덮어쓰지 않는다. 서로 다른 옛 설정 원본은 카탈로그의 공간별 이전 기록에 보존한다. 삭제한 공통 모델 ID는 삭제 목록으로 재유입을 막는다. 설정 기록은 비밀 원문 대신 기존 참조만 보유한다.
- 쓰기 가능한 공간에는 변경된 값만 기존 삭제 SET NULL/CASCADE·참조 검증·CAS를 거쳐 반영한다. 모델 삭제 후 다른 공간의 대화·에이전트 참조도 재열기 시 기존 삭제 규칙대로 정리한다. 매 조회·화면 렌더마다 쓰지 않으며 같은 값 재투영은 저장 세대를 올리지 않는다.
- 읽기 전용 공간은 메모리 조회 세대에만 공통 설정을 투영한다. 원본 파일·저널·체크포인트·저장 순번을 변경하지 않고 조회·표시에 같은 세대를 사용한다. 해당 공간에서 설정 편집·실행을 허용하는 변경은 아니다.
- 저장 순번 0인 빈 공간도 열 수 있다. 새 투영 레코드의 유효한 메타데이터를 위해 가상 조회 순번 1을 사용할 수 있으나 원본 `workspace.info.commit_seq`는 0 그대로다. 상태바는 이때를 포함한 읽기 전용 상태를 저장 세대로 오인하지 않도록 '읽기 전용 조회'로 표시한다. 쓰기 가능한 열기 응답은 투영이 끝난 실제 저장 순번을 반환한다.
- 공통 설정 변경은 공통 저널의 pending 의도 → 작업 공간의 실제 CAS 커밋 → 영수증을 확인한 공통 카탈로그 확정 순서다. 마지막 단계 전에 중단돼도 다음 실행에서 원래 공간의 영수증을 확인해 복구한다. 실패한 명령이나 미확정 쓰기를 저장 성공으로 표시하지 않는다.
- 미확정 공통 저장이 남은 상태에서 원래 공간 폴더가 이동·삭제되면 원래 위치를 복원해야 복구할 수 있다. 앱은 빈 기본값으로 초기화해 문제를 숨기지 않는다. 카탈로그 손상·지원하지 않는 형식·단일 writer 잠금 오류도 명시적으로 반환한다.
- API 키는 기존 OS 자격 증명 저장소의 SecretRef를 사용한다. 키를 평문 설정 파일로 복사하지 않는다. Linux Secret Service가 없어 세션 전용으로 저장한 키는 기존과 같이 앱 재시작 후 재입력이 필요하다. 공통화가 OS 비밀 저장소의 영속성을 대신하지 않는다.

스킬 원본은 `<앱 프로필>/shared-resources/skills`에 둔다. 기존 `resources/skills`는 공간 경로별로 한 번 가져오고 원본을 바꾸지 않는다. 메타데이터의 알 수 없는 필드·바이너리 보조 파일·빈 디렉터리를 보존하고, 충돌한 기존 원본은 `<앱 프로필>/shared-resource-imports/<경로 해시>/<이름>/<내용 해시>`에 보관한다. 기존 실행 스냅샷과 같은 64MiB/10,000항목 경계를 사용하며 링크·정션으로 경계를 벗어난 입력은 거부한다. 실행 capability는 여전히 공간의 `work/tasks/<task_id>`에 제한한다. 공통 원본은 실행 루트가 아니며, 읽기 전용 공간에서 파일 편집도 허용하지 않는다.

스킬 자동 이전의 삭제 이력은 프로필 리소스 정책으로 관리한다. 전체 스킬 삭제 전에 영속 기록하고, 아직 열지 않은 옛 공간에서도 삭제 이름을 자동 활성화하지 않는다. 그 원본 파일은 충돌 보관소에 보존한다. 명시적인 재생성은 허용하며 삭제 이력은 옛 파일의 자동 재수입만 차단한다. 일반 임베디드 호스트의 공간 리소스에는 이 프로필 정책을 강제로 적용하지 않는다.

## 검증 범위

아래 기본 회귀는 실제 사용자 API 키·외부 사이트를 사용하지 않는 격리 시험이다. 후속 모델 복구의 실제 저장값 읽기 전용 대조와 제품 경로를 통한 공통 설정 복구는 별도 항목에 기록한다. 사용자 지시를 따라 실제 OS 화면 자동 조작은 재개하지 않는다.

첫 workspace 검사에서는 트래픽 비활성/재설정 시험의 고정 드라이브 구간에서 활성 폴링을 관측하지 못했다. 해당 시험은 40회 × 1ms 대기 방식이며 당시 최적화 빌드가 겹쳤지만 원인을 단정하지 않는다. `traffic_runtime.rs`를 바꾸지 않고 격리 1건 및 RPC 전체 148건이 이후 통과했다. 최초 실패·재시험은 각각 원래 로그로 남긴다. 공통 설정 검토 중 발견한 검색 SecretRef 검증 누락은 최종 입력 고정 전에 수정했고, 잘못된 문자열·숫자·null·빈 객체를 거부하는 시험으로 재검증했다.

새 빌드 후보는 59,926,200바이트, SHA-256 `146d0ef077c3ab238ca340a03ef0f10c5547650d0e0eed671b1ac05e3919bcb5`다. 빌드 명령은 표준 `python desktop/native/scripts/build.py`이며 컴파일은 성공했다. 실행 중인 앱 때문에 최종 설치만 실패하여 `desktop/dist/ARTEX-Windows/ARTEX.exe`에는 이전 보고서 버전(SHA-256 `17482551e661f2f1c80c7b0de1d8fe891eb9cc59e930a2a03c5d1dc86b4b5870`)이 보존돼 있다. 캐시의 빌드 후보로 비대화형 자체 시험을 수행했으며 이를 표준 실행 파일 적용 완료로 설명하지 않는다. 앱의 **파일 → 앱 종료** 또는 트레이 **저장 후 종료 / Quit**로 정상 종료한 후 같은 표준 빌드 명령을 다시 실행하면 설치할 수 있다. 커밋·푸시·릴리스 업로드는 하지 않았다.
