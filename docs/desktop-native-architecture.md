# Rust 통합형 데스크톱 앱 설계

2026-10-14 소스 폴더 정리 후 프로젝트 루트는 `D:/Artex/rebuilt`이며 현재 UI·서비스는 `desktop/native`, `desktop/native-core`에 있다. 기존 Go/Web와 Git 이력은 별도 `D:/Artex/original`에 보존했다. 일반 Cargo 빌드는 고정 계약·리소스를 사용해 원본 폴더에 의존하지 않는다. 원본 비교 도구만 `scripts/source-layout.mjs`와 `ARTEX_ORIGINAL_ROOT` 설정으로 원본을 읽는다. 과거 검증 결과의 절대 경로는 당시 증거로 유지한다.

## 2026-10-14 대화·작업 수명 주기와 실행 제어

네이티브 Rust 채널에 `NativeQuery::AgentMonitor`, `DeletionPreview`, `ConversationTrash`와 `NativeAction::RunControl`, `ConversationManage`, `TaskDelete`를 추가한다. 기존 v1 RPC에 선언되지 않은 메서드를 노출하지 않는다. 모든 변이는 `WorkspaceScope`, 고유 command ID, 미리보기 당시의 모든 `Expected` 버전을 필요로 한다. 비동기 응답은 원래 작업 공간·열린 세대·UI 요청 토큰과 일치해야 적용한다. 다른 항목을 선택하거나 자동 조회가 갱신돼도 확인 중인 대상·버전을 바꾸지 않는다. 충돌은 명시적으로 다시 확인해야 한다.

대화 기록 조회는 자동 갱신과 수동 조회 모두 요청 전에 대화 ID와 토큰을 고정한다. 기록 캐시는 대화별로 구분한다. 내역 비우기·휴지통·영구 삭제에서 실제 성공한 대화의 이전 조회만 폐기하고 빈 권위 캐시를 두어 갱신 전 스냅샷의 기록도 표시하지 않는다. 이후 새 조회는 정상 적용하며 다른 대화의 캐시·초안·진행 중 조회를 보존한다. 단순 실행 중지는 기록을 폐기하지 않는다.

대화에 선택적 `trashed_at` UTC와 `trash_generation`(`trash_` + 32자리 hex)을 저장한다. 없는 필드도 기존 객체로 인정하며 v1 DTO에 네이티브 확장 필드를 섞지 않는다. 휴지통은 메타데이터만 바꾸고 기본 목록·전송에서 제외한다. 복원은 동일한 객체·기록을 유지한다. 내역 비우기와 영구 삭제는 대화 전용 활동·질문·보조 세션 및 전용 디렉터리를 정리한다. 도구·LLM 감사 기록과 공유 출처는 명시한 보존 정책을 따른다. 작업 삭제 옵션은 기본적으로 모두 꺼져 있고 기존 작업 보관·복원은 계속 제공한다.

삭제 조정자는 실행 admission을 동결하고 취소한 후 `run.stop` 또는 `run.force_stop`을 소유한 run ID·engine epoch의 호스트 Context로 전달한다. 임의 PID나 다른 실행 ID는 받지 않는다. 셸·Python·도구 프로세스, PTY, stdio MCP와 진행 중 공급자·도구 호출을 포함한다. `accepted`는 종료 증명이 아니다. Windows는 프로세스 leader 회수·JobObject ActiveProcesses=0·출력 I/O 완료와 in-flight 호스트 호출=0을 확인한다. Unix는 그룹을 이탈한 자손을 완전하게 입증할 수 없으므로 미확인으로 표시하며, 회수된 leader의 PGID에 다시 신호를 보내지 않는다. 모니터 조회 시간 초과는 실행을 중지하지 않는다.

종료 영수증은 기존 `command_receipts`의 `native.lifecycle.cleanup`에 run ID·epoch·정리 상태·검증 결과로 저장한다. 이전 epoch의 미확인 상태를 새 빈 레지스트리로 덮어써 종료 성공으로 인정하지 않는다. 파일 삭제 전 `work_root/tasks/<task_id>` 또는 `work_root/conversations/<conversation_id>`만 격리한다. CAS·취소 실패는 파일을 복원한 뒤 admission을 해제하며, 미확인 복원은 `RECOVERY_REQUIRED`로 보고한다. 성공 시 그래프 변경 후 파일 fence를 해제한다. 공유 디렉터리·원본 업로드·다른 작업 파일을 대상으로 삼지 않는다. 기존 추가 관리의 삭제 명령도 같은 확인 조정자를 사용한다.

정상 종료에서는 controller 취소 후 실제 호스트 retirement를 확인하고 `HostGateway::retirement_report`로 현재 epoch의 모든 유효한 소유 실행 증거를 받는다. 검증한 영수증을 저장·체크포인트한 뒤 저장소를 닫아, 다시 열린 공간에서도 정상 종료한 실행의 삭제가 가능하다. 기본 gateway의 빈 보고서와 이전 epoch는 증거로 사용하지 않는다. 유효하지 않은 참조를 가짜 소유권으로 대체하지 않는다. Unix의 미확인 자손은 정상 종료 후에도 미확인으로 남는다. 모델 요청·출력 정리가 진행 중이면 기한 안에서 관찰 조회를 재시도하고, 취소·기한 만료는 삭제를 확정하지 않는다.

실행 모니터는 200개 이하 페이지로 실제 controller 단계·승인/질문 대기·도구 및 이벤트의 마지막 진행을 보여준다. 조회 시각과 진행 시각을 분리하고 실제 생존 신호를 수집하지 않은 경우 `heartbeat_at=null`, `heartbeat_source=not_recorded`로 반환한다. 수치 진행률을 추정하지 않는다. 일반 중지는 즉시 대기 상태를 표시하고 강제 종료·삭제는 영향 확인을 제공한다. 작업 전체 중지는 task 배정을 일시 정지하고 해당 task의 소유 실행만 제어한다. 최종 검증 근거와 OS 수락시험 한계는 native/STATUS.md 및 desktop-platform-audit.md에 기록한다.

2026년 10월 13일 사용자 지시를 반영한 구현 기준이다. 기존 React·Tauri·별도 엔진 실행 파일 방식은 사용자가 거부한 이전 구현이며, 새 앱의 완료 근거로 사용할 수 없다. 기존 소스와 데이터 형식은 기능 비교·이전 및 검증된 라이브러리 재사용을 위해 보존한다.

제품 코드의 언어는 Rust다. Rust UI, 에이전트 실행, 도구 감독, 객체 그래프와 파일 저장을 하나의 앱 프로세스에 통합한다. 웹 화면, JavaScript, WebView, 애플리케이션용 HTTP 서버, 별도 엔진 실행 파일 및 UI용 파이프 RPC를 새 앱의 실행 조건으로 두지 않는다.

## 실행과 상태 소유권

메인 스레드는 egui/eframe으로 OS 창과 Rust 위젯을 그린다. 저장·에이전트 상태를 소유하는 작업 스레드 하나가 변경 명령을 직렬화한다. UI는 제한된 Rust 채널에 타입이 있는 명령을 제출하고 완료·진행 이벤트를 받는다. UI는 네트워크·디스크 작업 완료를 기다리며 멈추지 않는다. 창을 닫을 때는 변경 확정·도구 정리·체크포인트 결과를 확인한다.

객체 조회는 같은 프로세스에서 발행한 불변 ReadGeneration을 사용한다. UI의 선택·탭·검색·편집 상태는 Rust 앱 모델에 보관한다. 편집 시점의 객체 버전은 자동 새로고침으로 바꾸지 않으며 CAS 충돌 시 명시적 재조회가 필요하다. 에이전트와 UI가 동시에 객체를 변경해도 단일 writer와 기존 명령 영수증·버전 규칙을 유지한다.

LLM·외부 도구처럼 오래 걸리는 작업은 감독되는 별도 작업 스레드에서 실행하고 소유 스레드에 결과를 돌려준다. OS 프로세스로 제공되는 Nmap·셸·Python 스크립트·MCP 서버 등은 기존 도구의 실행 방식에 따라 외부 프로그램으로 실행할 수 있다. 앱의 UI나 엔진을 별도 프로세스로 실행하는 방식과 구분한다.

## 화면 구성

OS의 별도 제목줄 대신 메뉴와 창 조작을 앱 테마의 40px 제목줄로 통합한다. 메뉴·버튼·이동 영역을 분리하고 최소화·최대화/복원·더블 클릭·이동을 표준 viewport 명령으로 처리한다. 닫기는 기존 저장 확인·트레이·서비스 종료 경로에 연결하며 제목줄에서 즉시 종료하지 않는다. Windows/Linux는 장식을 끄고 네 변과 모서리의 초기 누름으로 크기 조절한다. macOS는 winit의 BeginResize 미지원 때문에 투명한 네이티브 제목줄과 전체 콘텐츠 설정을 사용하고 네이티브 크기 조절을 유지한다. 키보드 표시는 macOS Command와 다른 OS Ctrl을 구분한다. 이 분기와 실제 OS 검증의 한계는 [플랫폼 점검](desktop-platform-audit.md)을 따른다.

하단 출력과 대화 보조 관리는 하나의 전체 너비 drawer로 통합한다. Activity와 Management는 배타적인 표시 탭이며 기본은 닫힘이다. Management는 대화에서 기존 SourceOperations의 동일한 편집·제출 경로를 사용하고 다른 Section은 기존 inline 관리 위치를 유지한다. 대화 중앙에 별도의 관리 패널을 중복 렌더링하거나 공간을 예약하지 않는다. 탭 전환·접기는 표시 상태만 바꾸며 편집 토큰, 선택 객체, CAS, 비밀 입력, 대기 요청의 소유권을 유지한다. 대화를 떠나면 Management 표시를 Activity로 전환한다.

drawer는 좌측·우측 패널보다 먼저 그려 창 전체 폭을 사용한다. ScrollArea는 내용 길이에 맞춰 너비를 줄이지 않으며 짧은 로그와 긴 출력 모두 오른쪽에 스크롤바를 둔다. 최소 900×620 논리 창에서는 도구막대를 한 줄로 압축하고 drawer 본문이 약 60px 이상 보이도록 검사한다. 입력창·헤더 높이는 실제 한 번 렌더링한 결과로 측정하고 첨부·대기 상태 변경 시 갱신한다. 테스트는 실제 도구막대와 drawer 생성 함수를 공유하고 GPU 캡처에서 최종 할당된 본문 높이도 확인한다. 고정 모의 도구막대나 ScrollArea의 초기 inner_rect만으로 가시성을 판단하지 않는다.

URL 페이지 이동을 Rust 화면 상태·작업 탭·객체 선택으로 바꾼다. 작업 공간 탐색, 중앙 작업 화면, 객체 상세·편집 창, 하단 실행·승인·진단 영역을 갖는다. 대화·작업·자산·탐색 그래프·발견 사항·트래픽 증거·파일·설정 기능을 같은 앱 모델에 연결한다.

설정은 Rust 입력 필드·선택 상자·목록·토글을 사용한다. 일반 사용 흐름을 원시 JSON 편집으로 대체하지 않는다. API 키는 입력 동안만 UI 메모리에 보관하고 OS 비밀 저장소에 전달한다. 객체 파일에는 SecretRef만 기록한다. 한국어 글꼴은 배포 가능한 라이선스의 리소스를 포함한다.

### Linux 데스크톱 스타일과 작업 화면 개편

2026년 10월 13일 비교 시안의 추천 조합을 적용한다. A의 부드러운 Linux 스타일을 공통 디자인으로 사용하고, C의 넓은 대화 영역과 접을 수 있는 상세 패널, B의 작업 탭·실행 상태 구성을 결합한다. egui/eframe의 자체 Rust 컴포넌트를 유지한다. 공통 버튼·입력·팝업·상태 표시는 밝은/어두운 중성 테마, 파란 강조색, 부드러운 모서리와 여백을 사용한다. 중첩된 테두리 그룹은 제목·배경 명도·간격으로 정리하며 hover·키보드 focus·오류·선택 상태는 구분한다. 글꼴 의존성이 없는 Rust 아이콘을 유지한다.

탐색은 작업 공간/자산과 증거/실행/환경 설정/관리로 그룹화한다. 기존 23개 Section은 모두 탐색과 보기 메뉴에서 접근할 수 있다. 객체 검색·목록은 별도 분할 패널이며 선택 객체의 편집은 중앙, 현재 저장된 객체의 상태·관계는 우측 읽기 전용 패널에서 표시한다. 우측 패널은 좁은 창에서 자동으로 숨긴다. 하단 실행 기록은 필요할 때 펼치며 오류·실행 대기·현재 저장 세대는 상태 영역에서 확인한다.

대시보드는 실제 최근 작업, 승인·질문 대기, 에이전트 실행과 활동을 표시한다. 추정 진척률이나 시안의 예시 데이터는 제품에 넣지 않는다. 작업 상세의 개요/에이전트/발견 사항/증거 탭과 기존 목표·범위·탐색 기능을 유지한다. 대화는 구조화된 메시지와 접을 수 있는 도구 결과, 별도 입력 영역을 사용한다. 낮은 창에서 하단 패널을 펼쳐 입력 영역을 담을 수 없으면 전체 대화 패널 스크롤로 접근성을 유지한다.

단일 활성 Section과 기존 선택·초안 소유권을 유지한다. 복수 문서 탭이나 이동식 도킹을 도입하지 않는다. 대화의 우측 상세는 기본 접힘이며 사용자가 선택한 펼침/접힘 상태를 Section별로 현재 앱 세션 동안 보존한다. 작은 창에서 자동으로 상세 표시를 생략해도 저장된 표시 선택은 바꾸지 않는다. 대화 입력·첨부·참조·전송 동작을 하나의 부드러운 영역 안에 묶고 긴 도구 결과는 펼침 표시를 사용한다. 화면 전환과 최신 상태 조회는 기존 편집 버전, SHA, 첨부 소유권을 새로 기준잡지 않는다. 우측 패널은 스냅샷의 실제 관련 실행 상태만 표시하고 추가 조회·변경 명령을 생성하지 않는다. Ctrl+S는 체크포인트 기록이며 편집 초안의 저장 버튼과 구분한다. 기존 168개 보조 관리 작업은 동일한 계약·scope·토큰·확인 절차를 유지한다.

대화 입력 영역은 실제 렌더링한 높이를 표시 전용 상태에 보관해 헤더 아래 영역의 하단에 배치한다. 그 위의 기록 스크롤은 내용이 짧아도 남는 높이를 채운다. 창 크기·첨부·전송 대기 변경 시 실제 높이를 다시 확인하며, 높이 측정을 위해 입력·전송·첨부 동작을 두 번 렌더링하지 않는다. 표시 재계산은 일반 repaint만 요청하고 도메인 명령이나 저장 세대를 재실행하지 않는다. 매우 낮은 창의 전체 패널 스크롤과 함께 동작하는 배치도 검증한다.

### 작업 공간 승인 모드와 응답성

표시 상태는 도메인 상태와 별개로 관리한다. 항목 목록은 작은 창과 넓은 창의 표시 선택을 Section별로 기억하며 폭 경계에서는 히스테리시스로 반복 접힘을 방지한다. 표시 변경은 조회 기준 버전, 선택 객체와 편집 초안을 변경하지 않는다. 설정 기본 화면은 일반 설정이며 운영 레코드는 명시적인 고급 관리에서 접근한다. 모델 연결·응답·고급 항목을 나누되 기존 저장·비밀 값 참조·기본 지정의 CAS 경로를 유지한다. 연결 시험은 명시적 클릭으로 저장된 프로필에 요청하며 편집 중인 미저장 키를 사용하지 않는다.

중지·일시정지·재개 컨트롤은 현재 소유한 실행·작업 상태에 따라 표시하며 실제 처리는 기존 명령 검증이 결정한다. 날짜·시각은 RFC3339 UTC 원문을 현지 시간으로 변환하여 UTC 오프셋을 함께 표시한다. 변환 실패 시 원문을 보존하고 임의의 시각을 만들어 표시하지 않는다. 승인·실행의 표시 이름은 저장된 도구·에이전트·작업·상태에서 만들며 원래 ID와 원문은 상세 관리에 유지한다.

작업 공간별 `settings` 객체의 `approval_bypass` 값은 기본 `false`다. `ui.settings` 조회와 `ui.setSettings`의 선택적 boolean 필드로 읽고 저장하며, 기존 저널·CAS·읽기 전용 규칙을 적용한다. 전역 OS 프로필이나 개별 대화 설정으로 저장하지 않는다. 상단 도구막대는 현재 작업 공간의 저장된 모드와 변경 중 상태를 표시한다.

켜진 모드는 내부 도구 승인 대기와 LLM 실행 심사 대기를 생략한다. 명시적으로 차단된 실행, 계획 모드의 변경 금지, 도구 역할·대상 범위·경로 제한은 유지한다. 사용자의 일반 질문과 계획 승인에는 자동 답변하지 않는다. 이미 대기 중인 도구 승인도 같은 규칙에 따라 처리하고, 수동 거부 결정을 뒤집지 않는다. 실행 승인 감사 기록에는 자동 허용의 출처를 남기며 도구 결과와 연결한다. 공급자의 응답 거절이나 외부 서비스의 보안 설정은 변경하지 않는다.

승인·모드 변경·일시정지·중지를 포함한 사용자 변경 요청과 그 준비 단계는 용량 제한이 있는 동일 FIFO 대기열에서 처리한다. 일반 조회보다 먼저 처리하되 먼저 누른 중지 요청보다 나중 승인이 앞서지 않는다. 닫기·종료는 더 높은 우선순위를 유지하고 일반 요청도 계속 처리한다. 승인에도 기존 준비·버전 검증·확정 단계를 적용한다. 정확한 요청 객체와 버전에 속하는 UI 표시만 처리 중으로 바꾸고, 성공·실패를 받으면 해제한다. 승인 기록이 확정되면 해당 실행을 즉시 다시 확인한다. 실행 중인 다른 도구나 모델 응답이 끝나기를 기다려야 하는 경우는 별도 실행 상태로 표시한다.

중앙 영역은 스크롤 중에도 사용 가능한 가로 폭을 유지한다. 짧은 설정값은 라벨과 입력을 같은 행에 배치하고, 긴 설명·프롬프트·본문은 가로 폭을 사용하는 그룹에 배치한다. 작업 버튼은 연관된 기능별 도구막대로 묶고 좁은 창에서는 줄바꿈한다. 저장된 데이터 상세는 접을 수 있게 두되 실행·편집의 주요 버튼과 상태는 바로 확인할 수 있게 한다.

수동 규칙 승인에는 감사 기록의 사용자 판정 출처를 남긴다. 실행 세대·run ID·tool-use ID·도구 이름·정규화된 입력이 모두 같은 호출에서만 권한 승인으로 재사용한다. 자동 규칙이나 모델의 허용은 사용자의 판정이 아니다. 명시적 차단·계획 모드·이전 수동 거부·만료 상태를 우선하며 관련 없는 질문·실행으로 승인 범위를 넓히지 않는다.

수동 승인과 승인 대기 타임아웃은 기존 CAS 경합 규칙을 유지한다. 아직 결정되지 않은 객체에 대해 먼저 확정된 판정이 유효하며, 나중 판정은 버전 충돌로 거부된다. 확정된 수동 승인은 대기 기한이 지났다는 이유만으로 다시 승인 질문을 만들지 않는다. 자동 bypass는 대기 기한이 지난 미결정 객체를 자동 허용하지 않는다. 실행 자체의 기한·일시정지·종료 판정은 승인 여부와 별도로 실행 직전에 확인한다.

## 기존 기능의 재사용 경계

재사용 대상은 파일 저장·복구, 도메인 변경 계획, 에이전트 제어, LLM 공급자, 81개 도구 계약과 실행기, 승인·취소·증거·내부 메시지·SecretRef다. 웹 통신 계약이나 기존 화면을 새 제품의 UI 구조로 재사용하지 않는다. 기존 RPC 서비스는 공통 애플리케이션 명령 처리와 wire 어댑터로 분리한다. 새 앱은 wire 어댑터·hello 협상·프레임 직렬화를 호출하지 않는다.

## 작업 공간과 수명주기

앱 인스턴스 및 작업 공간의 OS 파일 잠금을 유지한다. 작업 공간을 바꾸기 전에 실행·편집 상태를 확인하고 이전 공간을 확정 종료한다. 작업 공간 세대와 실행 epoch가 바뀐 결과는 폐기한다. 절전·비정상 종료 뒤에는 불명확한 외부 실행을 자동 반복하지 않고 복구 상태로 표시한다.

파일 형식은 기존 객체 그래프·저널·스냅샷·Blob 계약을 유지하므로 기존 공간을 새 앱에서 열 수 있다. UI와 내부 명령 전송 방식의 변경을 이유로 사용자의 저장 파일을 일괄 재작성하지 않는다. PostgreSQL은 오프라인 이전 입력에만 사용한다.

## 수락 기준

- 새 실행 파일 하나로 Rust UI와 런타임이 함께 시작되며 엔진 실행 파일·WebView2·Node.js가 없어도 동작한다.
- 새 제품의 Cargo 의존성에 Tauri·wry·WebView UI 런타임이 없다.
- 작업 공간 만들기·재열기·객체 편집/CAS·실제 대화·작업 시작/취소·파일/도구·설정·증거 흐름을 새 UI 또는 동일 앱 명령 경로에서 검증한다.
- 새 경로의 테스트와 실행 결과를 별도로 기록한다. 이전 구현의 316개 테스트·24개 웹 화면 통과를 새 Rust UI 통과로 보고하지 않는다.
- macOS·Windows·Arch Linux의 실제 창·글꼴·파일 선택·저장·종료·프로세스 정리는 해당 OS에서 검증한다.

## 중단점과 재개 기록

사용량 제한 당시 새 native/native-core 디렉터리나 부분 소스는 생성되지 않았고 API 설계와 작업 분담에서 중단되었다. 재개 시 실행 중인 Cargo·Rust 컴파일러·ARTEX 프로세스가 없음을 확인했다. 기존 검증 로그 15개와 패키지 해시를 확인하고 164개 소스·계약 파일을 desktop/.resume/2026-10-13-native-restart에 복사해 해시를 남겼다. 새 작업은 desktop/native와 desktop/native-core에서 진행한다.
