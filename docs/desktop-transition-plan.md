# ARTEX 데스크톱 전환 계획

2026년 10월 13일 변경: 사용자 지시로 Rust UI·런타임·파일 저장을 단일 앱 프로세스에 통합한다. 새 구현 기준은 [Rust 통합형 설계](desktop-native-architecture.md)다. 이전 React·Tauri 패키지는 보존하며 새 제품의 검증과 구분한다. 작업 경로는 desktop/native와 desktop/native-core다.

2026년 10월 12일 갱신. 개발 비용보다 안정성과 정확성을 우선해 macOS·Windows·Arch Linux용 Rust 데스크톱 앱으로 전환한다. 업무 데이터는 메모리 객체 그래프와 파일 저장으로 관리하고 PostgreSQL을 기본 실행 의존성에서 제거한다.

구조는 [ARTEX 데스크톱 아키텍처 설계](desktop-architecture.md), 데이터·RPC·저장·내부 메시지·도구 계약은 [상세 구현 명세 v1.0](desktop-implementation-spec.md)에 정의한다. 54개 테이블·571개 필드, 261개 HTTP 경로, 258개 화면 API 함수와 [81개 도구 대응](desktop-tool-mapping.md)을 고정했다. 별도 desktop 디렉터리에 Rust 엔진·Tauri 앱·React 화면·도구 실행기·데이터 이전을 구현했다. 실제 검사 결과와 남은 OS·배포 환경 검증은 [구현 현황](../desktop/native/STATUS.md)과 [기능 비교](../desktop/native/PARITY.md)에 기록한다.

## 확정한 구조

| 영역 | 설계 결정 |
| --- | --- |
| 언어와 앱 | Rust 엔진과 Tauri 2 호스트, 기존 TypeScript·React 화면 재사용 |
| 프로세스 | 화면·앱 호스트와 별도 Rust 엔진, 외부 도구는 호스트가 감독 |
| 통신 | 전용 파이프의 버전이 있는 JSON RPC, 앱 제어용 HTTP 포트 기본 비활성화 |
| 데이터 | 작업 공간별 객체 소유권, 타입이 구분된 ID 관계, 단일 변경 처리 경로 |
| 에이전트 정보 공유 | SharedContextService와 공통 객체 저장소, 기존 직접 관계·읽기 전용 상속·도구 권한 유지 |
| 에이전트 알림과 통신 | 변경과 전달 대기 항목의 동시 저장, Brevduva 구조를 활용한 자체 내부 메시지 프로토콜 |
| 영속 저장 | JSON 스냅샷과 일괄 변경 프레임, 디스크 동기화 완료 후 성공 응답 |
| 동시 실행 | 사용자 프로필당 앱 하나, 작업 공간당 쓰기 엔진 하나와 OS 파일 잠금 |
| 기본 실행 환경 | 사용자 세션에서 직접 실행, PostgreSQL·Docker·시스템 서비스 필수 의존성 제거 |

Rust의 안전한 코드와 타입 검사를 사용하되 논리 오류·파일 손상·외부 프로그램의 부수 효과는 별도 설계와 검증으로 처리한다. 자체 unsafe는 도메인·저장 모듈에서 금지하고 OS 연동 경계로 격리한다. 초기 CPU 대상은 설계 선택이며 지원 완료를 의미하지 않는다.

## 데스크톱 동작

- 설치 경로는 읽기 전용 리소스와 실행 파일에 사용하고 상태·설정·로그는 사용자 데이터 경로에 저장한다.
- 서버 로그인 대신 작업 공간 만들기와 최근 작업 공간 열기로 진입한다. 자격 증명과 도구 정책은 별도로 유지한다.
- 창을 새로 고쳐도 엔진은 유지한다. 창 닫기는 기본 종료 절차를 시작하고 실행 중 작업은 일시 정지 후 종료를 기본 선택으로 제공한다.
- 백그라운드 실행은 사용자가 선택한 모드에서 제공한다. 트레이가 없는 환경에서 숨은 앱 상태를 만들지 않는다.
- 절전 복귀와 네트워크 재접속 후 실행 상태를 대조한다. 결과가 불명확한 외부 명령은 자동으로 다시 실행하지 않는다.
- 엔진 장애 시 화면을 유지하고 관리 프로세스를 정리한 뒤 제한된 재시작 또는 복구 화면을 제공한다.

## 데이터와 복구 보장

작업 공간은 회사·공유 자산·여러 작업·탐색·취약점·증거의 경계다. 객체 종류별 ID와 관계를 관리하고 객체 버전으로 충돌을 감지한다. 같은 작업 공간 안에서도 작업별 조회·도구 권한의 범위를 유지한다. 큰 기록과 트래픽은 파일에 두고 필요한 구간만 읽는다.

영속 변경은 검증, 필수 참조 파일 저장, 트랜잭션 프레임 기록과 동기화, 메모리 일괄 반영, 응답 순서로 수행한다. 성공 응답 이후의 변경은 검증한 저장 환경에서 재시작 후 복원되어야 한다. 저장 실패 시 새 변경을 멈추고 복구 절차를 거친다.

스냅샷은 확정 순번의 일관된 상태로 만든다. 최소 두 개의 유효 세대와 각 세대의 재생 기록을 유지한다. 마지막 미완성 프레임과 중간 손상을 구분하고, 최신 변경을 복원하지 못한 경우 누락 범위를 표시한다. 원본 파일을 보존한 복구본에서 검증한다.

외부 명령과 저장을 하나의 원자적 작업으로 취급하지 않는다. 실행 ID·상태·결과로 대조하며 불명확한 호출은 recovery_required로 남긴다. 앱 재시작이 외부 작업의 자동 재실행을 의미하지 않는다.

## 에이전트 공유와 내부 메시지

기존 DB 기반 공유 기능을 유지한다. 에이전트는 SharedContextService를 통해 같은 WorkspaceStore에 사실·자산·취약점·작업 결과를 기록하고 읽는다. 파일은 영속화와 복구를 담당하며 각 에이전트가 파일을 직접 수정하는 방식으로 공유하지 않는다.

- 같은 작업의 공유 상태와 직접 연결된 원본 작업의 읽기 전용 정보를 제공한다. 원본의 원본을 재귀 상속하지 않는다.
- source_task_id·inherited 표시, 원본 작업 변경의 다음 조회 반영, 관계 제거·삭제·권한 철회를 유지한다.
- 결과·실행 기록의 상속은 기존 허용 종료 상태와 조회 필터를 유지한다. 공용 자산과 작업별 실행 범위는 구분한다.
- add_hint·add_task_hint·발견·완료·보고서 트리거는 확정 객체를 참조한다. 대상·도구 바인딩·병합·실행 정책을 유지한다.
- 객체 변경과 전달 대기 항목을 함께 저장하고, 이벤트 ID·활성화 키·처리 기록으로 재전달을 판정한다. 저장 후 알림 전 종료도 복구한다.
- steer_work 지시는 실행 ID에 묶어 다음 도구 호출 전에 전달하며 종료된 실행의 지시를 다른 실행에 적용하지 않는다.

Brevduva의 식별·채널·send·request·reply·report·receipt·acknowledge 구조를 참고해 ARTEX 자체 내부 프로토콜을 구현한다. AgentMessageRouter가 메시지를 전달하고 WorkspaceStore가 요청·수신 확인·처리 상태를 보존한다. command_id·message_id·correlation_id로 중복과 답변을 판정하며 관찰과 업무 완료를 구분한다. Brevduva 서비스·데몬·MCP 브리지·SDK는 의존성에 추가하지 않는다.

자세한 조회 범위·저장 후 알림·프로토콜 대응과 비교 시나리오는 [아키텍처의 에이전트 공유 설계](desktop-architecture.md#에이전트-간-정보-공유)와 [내부 통신 프로토콜](desktop-architecture.md#brevduva-구조를-활용한-내부-통신-프로토콜)을 따른다.

현재 ARTEX에 연결되지 않은 SDK 도구 5개는 구현 대상으로 확정하고 agent별 선택 활성화·기본 비활성화로 제공한다. 1단계의 데이터·RPC·저장·메시지·81개 도구 매핑과 수락 시나리오 정의는 완료했으며, Go/Rust 실행 결과 대조 및 장애 시험은 2단계 이후 수행한다. 도구 정의 수와 실제 제공 기능 수를 구분한다. Rust 전환 과정에서 기존 동작의 오류를 무조건 복제하지 않는다.

2026-10-12 구현을 별도 [desktop 작업 디렉터리](../desktop/README.md)에서 시작했다. 저장 코어와 내부 메시지의 회귀·장애 주입 시험, 도메인 서비스 일부 Go 입력 대조, Windows 네이티브 호스트 및 기본 화면을 구현했다. 2·3·4·5·6단계의 일부를 함께 통합한 상태이며, 이를 해당 단계의 전체 수락 기준 통과로 간주하지 않는다. LLM 실행 controller, 원본 화면/전체 도구 흐름, 데이터 이전 및 세 OS 배포 검증은 남아 있다. 현재 상태는 [구현 현황](../desktop/native/STATUS.md)과 [기능 차이 표](../desktop/native/PARITY.md)에 기록하고, 수정 결과의 전체 반복 검증 기록을 유지한다.

## 기존 코드에서 확인한 전환 항목

- selfupdate/github.go의 Autumn-27/artex 업데이트 경로는 데스크톱판에서 사용하지 않는다.
- web/src/lib/api.ts의 HTTP·SSE·JWT 의존성은 데스크톱 전송 계층으로 분리한다.
- norma/tool/pty_other.go의 Windows 대화형 터미널 미지원은 ConPTY 구현과 검증으로 해결한다.
- llmpool/pool.go의 스트리밍 이후 모델 전환 제한과 도구 호출 중복 방지 계약을 유지한다.
- db/schema.sql의 자격 증명은 OS 비밀 저장소로 옮기고 업무 객체는 파일 형식으로 이전한다.
- traffic/traffic.go의 SQLite 인덱스와 평문 기록은 새 검색 캐시·객체 기록·접근 정책으로 전환한다.
- db/exploration_sources.go와 agent/blackboard_inheritance_test.go의 직접 상속·조회 필터·읽기 전용 계약을 Rust 비교 시나리오로 옮긴다.
- server/manager.go·server/engine.go의 알림과 메모리 수정 지시 큐를 저장된 이벤트·전달 상태로 강화한다.
- LICENSE의 AGPLv3와 재사용 리소스·의존성 조건을 배포 목록에 반영한다.

## 구현 중 확정할 릴리스 입력

상세 구조를 다시 미정으로 두지 않고 다음 값을 실제 패키지 검증으로 확정한다.

- 최소 OS 버전과 WebView·파일 시스템의 지원 조합.
- 대표 데이터셋과 메모리·조회·저장·복원 시간의 수치 기준.
- 자체 배포 위치와 앱 식별자, 업데이트 검증 키 및 배포 서명 계정.
- 외부 도구별 기본 포함 범위와 고정 버전.
- 프로젝트 전체 암호화와 Linux 대체 비밀 저장소의 제공 범위.

이 설계 반영은 실행 코드 전환 완료와 구분한다. 현행 Go 서버의 실행 방법은 Rust 구현 및 패키징 완료 전까지 현행 기능의 기준으로 유지한다.
