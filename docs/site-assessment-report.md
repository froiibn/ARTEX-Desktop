# 사이트 분석 종합 결과 보고서

2026년 10월 20일 · 사용자가 요청한 기능 추가

사이트 분석 작업에서 **무엇을 검사했고, 어떤 문제가 발견됐으며, 무엇부터 개선하고 어떤 검증이 남았는지** 한 보고서에서 확인한다. 보고서 단위는 선택한 분석 작업이다. 다른 작업의 자산·발견·실행 기록을 전체 작업 공간 통계로 섞지 않는다. 한 작업에 여러 대상이 있으면 그 작업에 등록된 범위를 함께 표시한다.

## 화면에서 확인하고 저장하기

1. **작업** 화면에서 분석한 작업을 선택한다.
2. **종합 보고서** 탭을 연다. 작업이 완료되면 종료 보고서, 실행 중·중지·실패·복구가 필요하면 상태에 맞는 부분 보고서를 확인한다.
3. **보고서 내보내기 (.md)**를 눌러 저장 위치를 선택한다. 선택한 보고서의 전체 Markdown 원문을 저장한다. 짧은 보고서는 **보고서 복사**, 큰 보고서는 **현재 페이지 복사**도 사용할 수 있다.

큰 보고서는 본문을 페이지로 나누어 표시한다. **이전 페이지·다음 페이지**로 이동하며, 파일 내보내기는 현재 페이지만 저장하지 않고 전체 원문을 저장한다. 페이지가 증거 중간에서 시작할 수 있어 페이지 본문은 Markdown 원문 그대로 표시한다. 작은 보고서는 제목·목록·근거 구분을 적용한 네이티브 보기로 표시한다.

보고서를 열어둔 동안 작업 종료나 남은 실행 정리 상태가 바뀌면 갱신한다. 그 밖의 저장 기록이 추가되면 기준 세대 안내와 함께 **보고서 다시 불러오기**로 최신 상태를 조회한다. 다른 작업이 계속 기록을 저장해도 읽던 페이지를 자동으로 처음부터 다시 열지 않는다.

## 보고서 내용

| 부분 | 포함하는 실제 기록 |
|---|---|
| 분석 개요 | 선택 작업·목표·저장된 상태·시작/종료 기록·보고서 기준 세대·남은 실행 |
| 대상과 범위 | 작업 범위·제약·연결 자산. 자산 등록과 검사 완료를 구분 |
| 검사 내역 | 목표·실행 의도·실제 도구 호출과 상태·활동·관찰·미완료 할 일·힌트 |
| 발견 문제 | 저장된 발견 상태·위험도·요약·실제 증거·기존 상세 보고서의 원인/영향/개선안·증거 버전 |
| 개선 우선순위 | 저장 위험도와 처리 상태에 따른 대응 순서. 해결·오탐·제외 기록은 별도 검토 대상으로 구분 |
| 미검증 항목 | 미실행·차단·실패·취소·답변 대기·결과/증거/개선안 누락·오래된 보고서·복구 필요 |
| 최종 판단 | 저장 범위에서의 결과와 후속 검증·수정·재점검 방향 |

도구 성공은 해당 호출의 실행 상태다. 보안 검사 통과나 취약점 부재로 바꾸어 표시하지 않는다. 발견 사항이 0개여도 사이트 전체가 안전하다는 결론을 만들지 않는다. 실행 계획·힌트만 등록된 항목을 실제 수행 검사로 집계하지 않는다.

구체적인 수정안은 저장된 취약점 상세 보고서를 포함해 전달한다. 상세 보고서가 없으면 개선안 작성이 필요하다고 표시하며 새로운 기술적 수정안을 만들어내지 않는다. 우선순위 P0–P3은 기록된 위험도의 분류이며, 실제 사업 영향이나 악용 가능성을 새로 평가한 점수가 아니다.

## 생성과 저장 계약

기존 `ui.report({task: TaskId}) → Body`를 확장한다. 저장된 객체·본문 파일을 불변 조회 세대에서 읽어 한국어 Markdown을 생성한다. 보고서 조회만으로 모델 요청·도구 실행·새 분석·저장 세대 증가를 일으키지 않는다. 보고서 전용 DB나 저장 형식은 추가하지 않는다. 같은 저장 세대에서는 같은 바이트를 만들고, 작업 공간 재열기 후 저장된 분석 기록으로 다시 구성한다. 특정 시점의 산출물을 별도로 보존하려면 파일로 내보낸다.

원본의 단순 작업 보고서를 확장하고 별도 native 탭·내보내기를 제공하는 것은 사용자 지시의 명시적 변경이다. 81개 도구·LLM prompt·원본 입력/출력 Body 계약·저장 스키마는 바꾸지 않는다.

- 대상: 현재 작업의 탐색 노드, 소유 실행·호출, 작업 자산 관계, 발견·증거·기존 상세 보고서. 공유받은 다른 작업의 실행을 자체 검사 실적으로 합산하지 않는다.
- 종료: 작업의 `done`만으로 충분하지 않다. 일시정지/큐·활성 실행·미종결 도구·복구 필요 상태를 함께 확인한다. 보고서 종료 표시는 외부 자원 정리 성공의 증명이 아니다.
- 근거: 발견 본문과 상세 보고서는 검증된 Blob까지 온전히 읽는다. 누락·손상·잘못된 본문이면 오류를 표시하고 빈 성공 보고서를 만들지 않는다.
- 정보 범위: 임의 도구 입력/결과에는 키·모델 문맥·공유 자료가 포함될 수 있어 원문 전체를 복제하지 않는다. 호출·상태·결과 존재·오류 여부와 원래 실행 상세 참조를 표시한다. 발견 증거·저장된 상세 보고서는 포함되므로 외부 공유 전 그 내용을 확인한다.
- 표시: 내부 Rust `NativeQuery::BodyPage`는 기존 `NATIVE_BODY_PAGE_BYTES` 정책으로 본문을 나누고 전체 원문의 길이·무결성과 UTF-8 경계를 확인한다. 기존 일반 본문 읽기 한도를 늘리지 않는다. 페이지 오류는 명시하며 자동 재시도를 반복하지 않는다.
- 격리: 작업 선택·작업 공간·실행 세대·부모 요청 토큰이 달라지면 지연 응답과 페이지를 폐기한다. 새 조회 전 이전 본문과 내보내기 대상을 함께 폐기한다.
- 내보내기: 화면의 같은 원본 Body를 기존 `StageBody → SaveFile` 경로에 전달한다. 저장 위치 선택·읽기 전용 원본 보호·범위·512 MiB 전체 스테이징 예산·취소/실패 처리를 유지한다. 파일 대화상자 취소는 저장 성공이 아니다.

## 검증 범위와 근거

검증은 사용자 API 키·운영 사이트·사용자 작업 공간을 사용하지 않는 로컬 fixture에서 수행한다. 도메인·실제 공개 명령·앱 서비스·실제 egui 입력·파일 저장·재열기를 구분해 결과를 기록한다. 최종 실행 결과와 소스 해시는 저장소 밖 `.organization/site-report-20261020`에 보존한다.

수락 대상은 선택 작업 격리, 비어 있지 않은 발견/증거/개선안, 계획과 실제 호출 구분, 부분/종료 보고서, Blob 오류, 1,000건 초과 발견, 기존 일반 본문 한도 초과 페이지, UTF-8·오래된 응답 차단, 화면 조회·전체 원문 내보내기, 읽기 전용 재열기다. OS 화면 자동 조작 중단 지시는 유지하며 실제 OS 저장 대화상자 조작과 macOS/Arch 실기기 검증은 이 로컬 헤드리스 시험으로 대신하지 않는다.

각 묶음은 중복되므로 고유 시험 총수로 합산하지 않는다. 새 domain 시험 8건과 내부 페이지 시험 4건·완료된 공개 도구 흐름 시험 1건은 공유 회귀에 포함된다. 새 UI 시험 6건도 UI 전체에 포함된다. 이 중 실제 App 연결 시험은 부분/중지 보고서 사례이며 완료·남은 자식·대용량 내보내기의 별도 시험을 같은 fixture의 모든 경로 수락으로 합산하지 않는다.

최초 호스트 회귀에서는 자격 증명 조회의 `FEATURE_DISABLED`와 자손 프로세스 시험의 빈 PID 파싱으로 2건이 실패했다. 같은 소스의 개별 재실행·호스트 전체 재실행·후속 공유 회귀는 통과했다. 해당 호스트 제품 코드는 이번 기능에서 수정하지 않았다. 최초 실패 로그는 보존하며, Windows 자격 증명 조회의 직접 원인은 미확정으로 남긴다. 빈 PID는 시험이 파일 존재만 기다리는 관측 경계도 확인됐지만 재실행 성공만으로 최초 원인을 확정하지 않는다. 이 결과로 운영체제 안정성 문제까지 모두 해결됐다고 선언하지 않는다.
