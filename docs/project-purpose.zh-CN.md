# ARTEX Desktop 项目目的

[한국어](project-purpose.md) · [English](project-purpose.en.md) · **简体中文**

ARTEX Desktop 是一款 Rust 原生桌面应用，用于在用户电脑上管理 LLM 辅助安全测试的任务、智能体、工具和证据。它是基于原版 ARTEX 的工作流程、提示词和工具契约重构的修改版本。目前整体项目使用 AGPL-3.0-only 许可证。

用户配置模型、目标和工作范围后，智能体拆分目标并调用工具，用户可以在一个界面中查看对话、审批、执行状态、停止控制和结果。资产、发现事项、执行记录、文件和证据关联到工作空间，用于编写报告和复测。81 个已注册工具包含文件、命令、MCP、任务管理和信息记录功能，并不意味着产品会安装 81 种独立的安全扫描器。

## 为什么改为桌面应用

核心目的是让**非开发者和普通用户无需开发环境或服务器运维知识，也能像使用普通桌面程序一样使用 ARTEX**。原版 Docker Compose 部署需要安装 Docker，并配置容器和 PostgreSQL；从源码构建则需要开发工具和对构建流程的理解。这些安装和配置过程构成了普通用户的使用门槛。

项目希望用户下载可执行文件，打开应用，配置工作空间和 LLM 模型后，即可在界面中开始工作。在保留原版智能体工作流程和工具契约的同时，减少准备与运维负担，将对话、任务和执行结果整合到一个程序中。

**减少安装与运维负担。** 基本应用运行不再要求安装、配置或管理 Docker、容器、Web 服务器和 PostgreSQL。针对桌面本地工作空间，使用对象图和持久化文件重新设计存储，通过对象关系、权限和持久化存储保留智能体间的信息共享。这一选择以简化个人电脑上的运行配置为出发点。

**将工作与执行控制整合到一个界面。** 在应用内查看对话、任务列表、智能体状态、工具审批、停止执行和结果。由于本地文件和外部程序都在用户电脑上处理，执行状态及终止过程按应用的生命周期进行管理。

**让数据和凭据适应本地环境。** 在基于文件的工作空间中关联保存对话、资产、发现事项和证据，API 密钥优先使用操作系统凭据存储。模型调用和远程工具运行所需的通信与配置的服务进行。

**使用 Rust 统一 UI 与应用服务。** UI、存储、智能体和执行服务在同一进程内运行，基本运行不再需要单独启动服务器或连接不同服务进程。在一个应用结构中管理存储、审批、取消和关闭，为 Windows、macOS 和 Arch Linux 共享开发与验证基础。各操作系统仍需分别完成打包及实际运行验证。

| 组成 | 原版 ARTEX | 当前 ARTEX Desktop |
| --- | --- | --- |
| 基本运行 | Go Web 服务器与 Next.js 界面 | 原生 UI 与应用服务在同一 Rust 进程内运行 |
| 工作信息 | 基于 PostgreSQL 的共享 | 对象图与持久化文件存储，通过明确的对象关系和权限共享 |
| 开始使用 | 通过 Docker Compose 等方式部署服务器和数据库后访问 Web 界面 | 下载可执行文件，运行应用并创建或打开本地工作空间 |
| 工具执行 | 服务器环境中的外部程序 | 根据需要运行并监督用户电脑上的程序 |
| 凭据 | 服务器配置与存储体系 | 优先使用操作系统凭据存储，对象中保存引用 |

原生应用的基本运行不需要独立的 Go 服务器、JavaScript 前端、WebView 或 PostgreSQL。此前的 Tauri/React 代码和独立引擎客户端已从当前工作树中移除。Python、Nmap、Shell 和用户配置的 MCP 等外部程序并未全部用 Rust 重新实现。

## 为什么将内置提示词转换为英文

LLM 提示词的行为会随模型和配置变化。即使保留原版文字，也无法保证角色执行、工具调用和响应完全相同，因此内置提示词已在保留原版意图和上下文的基础上转换为英文。

英文转换保留了各智能体的角色与职责、工作范围、证据记录、结束条件，以及工具调用和输出契约。默认角色提示词、工作收尾提示词和审批判断提示词均使用英文。实际行为和结果需在所选模型、配置及执行环境中确认。对话和报告的默认响应语言是韩语，用户要求时可使用英语。

## 目标平台与公开目的

目标操作系统为 Windows、macOS 和 Arch Linux。目前已完成分发和实际 GUI 验证的平台是 Windows x64；macOS 和 Arch Linux 的实机验证及程序包仍待完成。

计划公开的目的是**帮助没有安全专业背景的用户，通过模拟渗透测试轻松分析并应对自己开发或运营的服务中的漏洞**。希望用户依据发现事项和证据理解问题，修改代码或改进安全配置后再次检查，从而提高服务的防御水平。

预期使用范围是对用户拥有或已获得明确测试授权的目标进行安全检查和研究。计划公开以让普通用户与开发者更容易开展安全检查，并通过发现、预防和修复漏洞支持防御性使用。
