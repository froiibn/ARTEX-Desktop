# ARTEX Desktop 프로젝트 목적

**한국어** · [English](project-purpose.en.md) · [简体中文](project-purpose.zh-CN.md)

ARTEX Desktop은 LLM 기반 보안 검증의 작업·에이전트·도구·증거를 사용자의 컴퓨터에서 관리하는 Rust 네이티브 데스크톱 앱이다. 원본 ARTEX의 작업 흐름과 프롬프트·도구 계약을 바탕으로 재구축한 수정 버전이며, 현재 전체 프로젝트 라이선스는 AGPL-3.0-only다.

사용자가 모델과 목표·작업 범위를 정하면 에이전트가 목표를 나누고 도구를 호출하며, 사용자는 대화·승인·실행 상태·중지·결과를 한 화면에서 확인한다. 자산, 발견 사항, 실행 기록, 파일과 증거를 작업 공간에 연결해 보고서 작성과 재검증에 활용한다. 81개 등록 도구에는 파일·명령·MCP·작업 관리와 정보 기록 기능이 포함된다. 독립된 보안 스캐너 81종을 함께 설치하는 제품이라는 뜻은 아니다.

## 데스크톱으로 바꾼 이유

핵심 목적은 **비개발자와 일반 사용자도 개발 환경이나 서버 운영 지식 없이, 일반적인 데스크톱 프로그램처럼 ARTEX를 사용할 수 있게 하는 것**이다. 원본의 Docker Compose 배포에는 Docker 설치와 컨테이너·PostgreSQL 설정이 필요했고, 직접 소스에서 빌드하는 방식에는 개발 도구와 빌드 과정에 대한 이해가 필요했다. 이러한 설치·설정 과정은 일반 사용자에게 진입 장벽이었다.

실행 파일을 내려받아 앱을 열고, 작업 공간과 LLM 모델을 설정한 뒤 화면에서 작업을 시작하는 흐름을 지향한다. 원본의 에이전트 작업 흐름과 도구 계약은 이어가면서 준비·운영 부담을 줄이고, 대화·작업·실행 결과를 한 프로그램에서 관리하도록 재구축했다.

**설치·운영 부담을 줄인다.** Docker·컨테이너·웹 서버·PostgreSQL을 설치·설정·운영하는 과정을 기본 실행에서 제외한다. 데스크톱의 로컬 작업 공간에 맞춰 객체 그래프와 파일 저장으로 재설계하며, 에이전트 간 정보 공유는 객체 관계·권한과 지속성 저장을 통해 유지한다. 이 선택의 기준은 개인 PC에서 필요한 구성의 단순화다.

**작업과 실행 제어를 한 화면에 모은다.** 대화, 작업 목록, 에이전트 현황, 도구 승인·중지와 실행 결과를 앱 안에서 확인하도록 구성한다. 로컬 파일과 외부 프로그램을 사용자의 컴퓨터에서 다루므로, 실행 상태와 종료를 앱의 생명주기에 맞춰 관리한다.

**데이터와 자격 증명을 로컬 환경에 맞춘다.** 대화·자산·발견 사항·증거를 파일 기반 작업 공간에 연결해 보관하고, API 키는 OS 자격 증명 저장소를 우선 사용한다. 모델 호출이나 원격 도구 실행에 필요한 통신은 설정한 서비스와 이루어진다.

**UI와 앱 서비스를 Rust로 통합한다.** UI·저장·에이전트·실행 서비스를 같은 프로세스에 구성해 별도 서버 실행과 프로세스 간 서비스 연결을 기본 실행에서 제외한다. 저장, 승인, 취소와 종료를 하나의 앱 구조에서 관리하고, Windows·macOS·Arch Linux용 개발·검증의 기반을 공유하려는 선택이다. 운영체제별 패키징과 실제 동작 검증은 각각 필요하다.

| 구성 | 원본 ARTEX | 현재 ARTEX Desktop |
| --- | --- | --- |
| 기본 실행 | Go 웹 서버와 Next.js 화면 | 네이티브 UI와 앱 서비스가 같은 Rust 프로세스에서 실행 |
| 작업 정보 | PostgreSQL 기반 공유 | 객체 그래프와 지속성 파일 저장, 명시적인 객체 관계·권한을 통한 공유 |
| 사용 시작 | Docker Compose 등으로 서버·DB를 배포한 후 웹 접속 | 실행 파일을 내려받아 앱 실행 후 로컬 작업 공간 생성·열기 |
| 도구 실행 | 서버 환경의 외부 프로그램 | 사용자 컴퓨터의 프로그램을 필요할 때 실행·감독 |
| 자격 증명 | 서버 설정·저장 체계 | OS 자격 증명 저장소를 우선 사용하고 객체에는 참조 저장 |

현재 네이티브 앱의 기본 실행에는 별도 Go 서버, JavaScript 프런트엔드, WebView, PostgreSQL이 필요하지 않다. 이전 Tauri/React 코드와 별도 엔진 클라이언트는 현재 작업 트리에서 제거했다. Python·Nmap·셸·사용자 MCP 등의 외부 프로그램을 모두 Rust로 다시 구현한 것은 아니다.

## 기본 프롬프트를 영문으로 바꾼 이유

LLM 프롬프트의 동작은 사용하는 모델과 설정에 따라 달라진다. 원본의 문장을 그대로 유지하더라도 역할 수행, 도구 호출과 응답이 동일하게 재현된다고 보장할 수 없으므로, 기본 프롬프트는 원본의 의도와 맥락을 유지한 영문으로 변환했다.

영문 변환 시 에이전트별 역할과 책임, 작업 범위, 증거 기록, 종료 조건 및 도구 호출·출력 계약을 유지하도록 구성했다. 기본 역할 프롬프트뿐 아니라 작업 마무리와 승인 판단 프롬프트에도 영문을 사용한다. 실제 동작과 결과는 선택한 모델·설정·실행 환경에서 확인하며, 대화와 보고서의 기본 응답 언어는 한국어이고 사용자의 요청에 따라 영어를 사용할 수 있다.

## 사용할 환경과 공개 목적

목표 운영체제는 Windows, macOS, Arch Linux다. 현재 배포·실제 GUI 검증을 완료한 대상은 Windows x64이며 macOS·Arch Linux 실기기 검증과 패키지 제공은 남아 있다.

공개하는 목적은 **보안 비전공자도 자신이 개발·운영하는 서비스에 모의침투를 수행해 취약점을 쉽게 분석하고 대응할 수 있도록 돕는 것**이다. 발견 사항과 증거를 바탕으로 문제를 이해하고, 코드 수정이나 보안 설정 개선 후 다시 점검하는 과정을 지원해 서비스의 방어 수준을 높이고자 한다.

제품이 지향하는 사용 범위는 사용자가 소유하거나 명시적으로 테스트 권한을 받은 대상의 보안 검증과 연구다. 일반 사용자와 개발자가 보안 점검에 접근하기 쉽게 하고, 취약점을 찾아 예방·수정하는 방어적 활용을 돕기 위해 공개한다.

원본 README의 별도 온라인·실무 사용 금지는 AGPL 제7·10조에 따른 [처리 방침](license-policy.md)으로 다루며 파생 프로젝트의 추가 라이선스 조건으로 채택하지 않는다. 방어적 사용 목적은 AGPL 권리를 제한하는 새 용도별 라이선스 조건이 아니다. 원작자·출처·무보증·수정·AGPL 고지와 실제 법률·별도 계약의 의무는 유지하며, 소프트웨어 라이선스가 대상 시스템에 대한 접근·검사 권한을 대신 부여하지 않는다.

2026-10-15에 현재 소스와 Windows `v0.2.0-preview.3` 시험 배포를 공개했다. 대응 소스와 라이선스 자료를 함께 제공하며 검증 범위는 [최종 산출물 기록](public-release-remediation-result-20261014.md)을 따른다. 이전 [라이선스 점검 결과](license-audit-20261014.md)는 당시 상태를 보여 주는 역사적 증거로 보존한다.

작업 데이터는 로컬에 보관하지만 LLM, 원격 MCP, 웹 요청과 외부 보안 도구를 사용하면 설정한 서비스·대상과 통신한다. 완전 오프라인 앱이나 외부로 정보가 전달되지 않는 앱으로 설명하지 않는다. 외부 도구·서비스의 이용 조건은 프로젝트 소스의 AGPL과 별도로 적용된다.
