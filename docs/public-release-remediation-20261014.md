# 공개 전 최종 검토의 수정 사항

최종 실행 파일·소스 ZIP·체크섬과 실제 검증 결과는 [후속 산출물 보고서](public-release-remediation-result-20261014.md)를 따른다.

2026-10-14. [이전 최종 보고서](public-release-final-review-20261014.md)의 지적 사항을 반영한 후속 기록이다. 이전 보고서는 당시 소스와 `preview.1`에 대한 증거로 보존한다. 저장소 공개 전환은 아직 수행하지 않는다.

## 반영한 수정

| 지적 사항 | 반영 내용 |
| --- | --- |
| 원본 README의 용도 제한과 목적 설명의 충돌 | AGPL 7·10조에 따른 [처리 방침](license-policy.md)을 기록하고 한국어·영어·중국어 README, 출처 안내와 목적 문서를 맞췄다. 원작자 고지와 AGPL 원문은 유지한다. |
| 앱 내 법적 안내 부족 | 정보 메뉴/F1에서 원작자·기여자, 수정 버전과 날짜, 무보증, AGPL 재배포권, 전체 라이선스와 정확한 빌드 소스 링크에 접근한다. 작은 창과 긴 라이선스는 스크롤한다. |
| 새 고지와 배포 파일의 불일치 | 고정 원문과 실제 바이너리 입력을 확인하는 수집기 및 검증된 실행 파일·동일 commit 소스 ZIP·체크섬을 만드는 배포 스크립트를 추가했다. 일반 README에는 원작자 중심 안내를 유지한다. |
| selectors/MPL 및 글꼴 고지 오류 | selectors의 실제 MPL 헤더와 원문, MPL 구성 요소의 정확한 소스, eframe 기본 글꼴의 저작권·라이선스를 매핑한다. |
| 정적 런타임 출처 불명확 | GNU 링크 맵과 고정 공식 배포의 원본 파일을 대조하고 GCC/MinGW 버전·런타임 예외·Rust 표준 라이브러리 출처를 보존한다. 삭제된 LTO 임시 파일의 원본 바이트를 검증했다고 주장하지 않는다. |
| 개발 PC 경로 노출 | 저장소·Cargo·rustup 경로를 치환한다. 배포 ZIP에서 실행 파일까지 알려진 사용자 홈·인증정보 패턴을 검사하며 원시 로그·링크 맵·시험 프로필은 제외한다. |
| 활성 CI 없음 | 수동 실행용 Windows/macOS/Arch 검증 workflow를 `.github/workflows/native-rust.yml`에 배치했다. 실제 실행 전 OS 통과를 주장하지 않는다. |
| 실제 macOS CI의 임시 경로 오류 | `/var`·`/tmp`의 정확한 시스템 별칭에 한해 root 소유·고정 대상·부모 권한을 확인한다. 임의 경로 전체를 canonicalize하지 않고 기존 사용자 링크/reparse 차단을 유지한다. 별칭 저장·체크포인트·재열기 및 사용자 링크 거부 시험을 추가했다. |
| 실제 CI의 시험 환경 차이 | APFS의 비 UTF-8 파일명 거부를 반영하되 잘못된 경로 요청·정상 후속 작업 검증은 유지한다. HTTP fixture의 불필요한 역방향 DNS를 제거하고 실제 요청 수신 후 취소를 검증한다. 초기 생성과 취소 완료의 시험 타이머를 분리하며 일반 완료 15초·네트워크 취소 2초 기준은 유지한다. 공통 Cargo 출력 경로로 중복 빌드도 줄였다. |
| 배포 검사에서 원문 예시 오탐 | 공식 Cargo archive와 대조한 4개 고지 파일의 공개 예시만 정확한 파일·SHA256·탐지 범주로 한정해 허용한다. 의존성 원문은 변경하지 않으며 파일 변조·다른 파일·소스 ZIP에서는 같은 문자열도 거부한다. |
| 창 캡처 및 실행 전달 검증의 종료 순서 | 정보 창의 등장 애니메이션 완료를 확인한 뒤 캡처한다. 두 번째 실행 검증에서는 확인 완료 신호 전까지 자동 종료를 보류하며 일반 앱 실행과 일반 캡처 모드는 유지한다. |
| Brevduva 참고 범위 불명확 | [구조 참고 대응표](brevduva-structure-reference.md)에 내부 메시지 모델의 대응과 구현 경계를 기록했다. 검증한 라이선스 기준 commit을 구현 당시 버전이라고 주장하지 않는다. |

## 확인한 시험

- 최종 native UI 시험은 102개이다. 최종 실행 결과는 후속 기록으로 식별한다. 정보 창의 실제 텍스트·전체 라이선스·작은 화면·소스 링크 검증을 포함한다.
- 전체 회귀 검증 통과. 변경하지 않은 공용 모듈의 기존 검증은 최종 공유 모듈 소스 해시 157개를 대조해 재사용했으며 native 서비스·host·UI·빌드·통합 자체 시험·실제 GUI 23개 영역·두 번째 실행 전달·정상 종료는 다시 실행했다.
- 실제 Windows GNU 빌드의 라이선스 수집에서 normal/build 후보 399개와 고지 파일 865개를 검증했다. 수집 결과는 실제 포함 수를 단정하는 목록이 아니다.
- 온라인/오프라인 수집 결과가 동일하며, 변조된 고지·캐시·패키지 원본, 알 수 없는 라이선스/정적 입력, 바이너리와 맵 불일치 등 8개 거절 시험이 통과했다.

최종 `preview.2`는 이 수정 사항을 담은 고정 소스에서 다시 빌드하고, 실행 파일·정보 창·라이선스 색인·소스 ZIP·체크섬을 함께 검증한다. 정확한 commit과 실행 파일 해시는 생성되는 `BUILD-INFO.json`, `SHA256SUMS.txt` 및 후속 결과 기록으로 식별한다. 검증 전 생성물은 배포하지 않는다.

## 과거 이력의 공개 범위

과거 일부 commit과 `preview.1` 소스 ZIP에는 현재 제거한 웹/Tauri 구현과 당시 누락된 고지가 남아 있다. 최신 commit에 고지를 추가해도 GitHub의 과거 commit/tag 소스 ZIP에는 추가되지 않는다. 릴리스를 Draft로 바꾸는 것만으로 과거 Git 이력의 소스 다운로드가 사라지지는 않는다.

따라서 공개 후보는 **현재 소스만 담은 새로운 Git 이력**으로 별도 준비한다. 기존 개발 이력·태그·시험 릴리스는 비공개 보관하고 삭제하지 않는 방안을 권장한다. 기존 저장소 이름/URL을 바꾸고 새 저장소에 후보를 등록하는 조치는 사용자 확인 후 수행한다. 후보 준비는 공개 전환을 의미하지 않는다.

## 남은 범위

배포 실행 파일은 Windows x64 GNU 대상이다. macOS CI는 서비스·저장·도구·UI 시험, release 빌드와 실제 통합 자체 시험을 확인했다. 원격 Windows/Arch GUI의 최종 상태와 정확한 검증 commit은 후속 결과 기록에 구분한다. macOS/Arch 실기기 검증, 코드 서명, 설치·자동 업데이트는 별도 후속 작업이다. Nmap/Python/MCP 등 외부 프로그램은 패키지에 재배포하지 않는다. 적용 법률·실제 별도 약정과 대상 접근 권한은 소프트웨어 라이선스와 구분한다. 이 기록은 모든 권리 관계의 법률적 보증이 아니다.
