# ARTEX Rust 데스크톱

현재 개발 대상은 Rust로 작성한 네이티브 데스크톱 앱이다. 화면은 egui/eframe이며 `native-core`의 객체·파일 저장, LLM 실행, 권한 검사와 같은 프로세스에서 실행된다. React, JavaScript, WebView, HTTP UI 서버, 별도 `artex-engine` 프로세스를 사용하지 않는다.

작업 디렉터리: `D:\Artex\rebuilt\desktop\native` (UI), `D:\Artex\rebuilt\desktop\native-core` (앱 서비스). 이전 Tauri/React 구현은 현재 작업 트리에서 제거했다. 데이터 저장은 기존 Rust 파일 포맷과 객체 ID를 유지한다. 임의 사용자 공간을 테스트 데이터로 쓰지 않는다.

## 빌드와 실행

Rust와 OS의 네이티브 빌드 도구가 필요하다. Node/npm 및 WebView 런타임은 필요하지 않다.

```powershell
Set-Location D:\Artex\rebuilt
$env:CARGO_TARGET_DIR = 'D:\Artex\rebuilt\desktop\target'
cargo build --manifest-path desktop/native/Cargo.toml
& D:\Artex\rebuilt\desktop\target\debug\artex-native.exe
```

앱에서 새 작업 공간을 만들거나 기존 공간 폴더를 연다. LLM 모델 메뉴에서 공급자·모델·API 키를 설정한 뒤 대화 또는 작업을 만든다. API 키 원문은 객체 저장에 쓰지 않고 OS 자격 증명 저장소의 참조로 기록한다. Linux에서 Secret Service를 사용할 수 없으면 세션 메모리 키라는 점을 화면에 표시한다. Windows/macOS에서 OS 저장에 실패하면 오류를 표시하며 저장 성공으로 처리하지 않는다.

모델 연결은 `API 키 입력 → 비밀 값 저장 → 설정 저장 → 목록에서 저장된 모델 선택 → 기본 모델로 설정` 순서다. 모델 설정 저장은 기본 모델 지정과 별개다. LLM 화면 상단에서 현재 기본 모델을 확인하며, 목록에서 기본 항목에 `· 기본`을 표시한다. 기본 지정은 저장된 설정에 적용하므로 편집 초안은 먼저 저장해야 변경값이 사용된다. `FEATURE_DISABLED: Configure an active LLM profile before sending a message`는 공급자에 연결하기 전 기본 모델을 찾지 못한 오류다. 기본 모델을 지정하거나 새 대화에서 저장된 모델을 명시적으로 선택한다.

Claude의 `stop_reason=refusal`은 모델 제공자의 요청 거절이다. 일반 대화가 연결된 상태에서도 특정 요청에 이 응답을 받을 수 있다. 앱은 거절을 명확하게 표시하고 같은 요청을 자동 반복하지 않는다. 모델 요청이 실패하면 확인된 사용량과 종료 사유를 오류 진단에 보존한다. 공급자 거절에는 도구 호출이 없으므로 해당 응답으로 보안 도구를 실행하지 않는다.

`Implementation produced a result outside the v1 contract`는 앱이 반환한 데이터 형식이 응답 규격과 맞지 않는다는 오류다. 도구 실행 승인 기록 때문에 화면 기록 조회가 실패하던 문제를 수정했다. 저장된 승인·감사 기록과 완료된 도구 결과는 그대로 유지한다. 화면 조회 오류는 진행 중인 분석의 실행 상태와 별개이며, 새 오류에는 문제가 난 요청 이름을 함께 표시한다.

상단 도구막대의 `Bypass`는 현재 작업 공간 전체의 도구 실행 승인 대기를 생략한다. 설정은 해당 작업 공간에 저장되며 다시 열어도 유지된다. 명시적 차단 규칙·계획 모드·대상 범위·경로 제한은 유지하며 일반 질문과 계획 승인은 직접 답해야 한다. 기본값은 꺼짐이다. 승인 출처는 실행 기록에 남고 읽기 전용 공간에서는 모드를 바꿀 수 없다.

승인 버튼을 누르면 즉시 처리 중 상태가 표시된다. 승인 요청은 일반 조회보다 먼저 처리하고 확정 후 해당 실행을 다시 확인한다. 정확히 같은 도구 호출에 대한 수동 규칙 승인은 권한 승인에서도 재사용하여 같은 실행을 두 번 승인하지 않게 한다. 자동 규칙·모델의 허용은 수동 승인으로 간주하지 않는다. 도구 실행이나 모델의 다음 응답 시간은 별도이며 실제 실행 완료 전에 완료된 것으로 표시하지 않는다.

```powershell
& D:\Artex\rebuilt\desktop\target\debug\artex-native.exe --workspace D:\사용자\작업공간
& D:\Artex\rebuilt\desktop\target\debug\artex-native.exe --workspace D:\사용자\작업공간 --read-only
```

`--profile`은 앱 설정/단일 인스턴스 잠금 경로를 별도로 지정한다. 검증 전용 `--self-test --workspace NEW_ABSOLUTE_PATH`는 새 폴더에서 실제 서비스·LLM 시험 공급자·파일 도구를 검사한다. `--smoke --workspace ABSOLUTE_PATH --screenshot ABSOLUTE_PNG_PATH`는 네이티브 창의 각 메뉴를 그린 뒤 화면을 저장하고 정상 종료한다. 기존 폴더를 `--self-test`로 덮어쓰지 않는다.

검증용 `--smoke-screen dashboard|tasks|sessions|chat|models|settings|approvals|files|archives`를 함께 지정하면 23개 화면 검사 후 해당 화면의 실제 저장 항목을 선택해 GPU 화면을 캡처한다. 기본은 대시보드다. `--smoke-narrow`는 `--smoke`와 함께 900×620 논리 크기의 최소 창을 검사할 때 사용한다. `--smoke-dock activity|management`는 같은 절차에서 하단 탭을 펼친다. 관리 탭의 캡처 대상은 `chat`이다. `--smoke-dialog delete-preview`는 대화·작업·보관 화면의 삭제 미리보기만 열고 실행하지 않는다. `--smoke-dialog trash`는 보관 화면의 대화 휴지통을 조회한다. 모든 화면 검증에는 격리된 시험 작업 공간과 별도 프로필을 사용한다.

## 작업 화면

대화·작업 목록의 체크박스로 여러 항목을 선택하고 `⋯` 또는 우클릭 메뉴에서 관리한다. 대화의 기본 삭제는 휴지통으로 이동이며 **보관·휴지통 → 대화 휴지통**에서 복원한다. **대화 내역 비우기**는 대화 설정을 유지하고 기록과 전용 파일을 정리한다. **영구 삭제**와 작업 삭제는 자료별 영향·전용 파일 경로·보존 자료를 확인한 후 확정한다. 작업의 보관·복원 기능은 유지한다. 공유 자료와 원래 업로드 파일은 전용 작업 디렉터리로 취급하지 않는다. 전용 파일은 활성 작업 영역에서 `.artex-host/quarantine`으로 격리하고 복구용 사본을 보존한다. 영구 삭제는 앱의 객체·활성 기록 삭제를 뜻하며 격리 사본·이전 WAL·백업의 물리적 제거 또는 보안 삭제는 보장하지 않는다.

**에이전트 실행** 화면에서 실제 실행 단계·대기 사유·마지막 진행·소유한 외부 실행·정리 상태를 조회한다. 별도 에이전트 생존 신호가 저장되지 않은 실행은 heartbeat를 **미기록**으로 표시한다. **중지**는 즉시 요청하고 중복 요청을 막으며, **강제 종료**는 확인 후 선택한 실행이 소유한 도구만 종료한다. 작업 전체 중지는 새 작업 배정도 일시 정지한다. 모델 제공자에 이미 전달한 요청은 로컬에서 취소하고 늦은 결과를 차단한다. 제공자의 서버 작업 종료를 보장하지 않는다.

**중지 요청됨**과 **정리 확인됨**을 구분한다. 파일·내역을 실제로 삭제하는 작업은 소유 실행 종료와 진행 중 호스트 호출의 종료가 확인된 후 확정한다. 확인 실패 시 자료를 유지하고 복구 필요 오류를 표시한다. 이전 앱 실행의 종료 확인 기록이 없는 데이터는 새 프로세스가 비어 있다는 이유로 삭제하지 않는다. 이 경우 대화 휴지통 이동은 가능하지만 내역 비우기·영구 삭제는 제한된다. Unix에서 프로세스 그룹을 이탈한 자손도 종료 미확인으로 처리한다.

Mac·Arch Linux 빌드 준비 조건과 아직 남은 운영 한계는 저장소의 `docs/desktop-platform-audit.md` 또는 배포 폴더의 `PLATFORM-AUDIT.md`에서 확인한다. 현재 배포 검증은 Windows이며 다른 OS의 실제 컴파일·실기기 실행 검증과 구분한다.

메뉴와 창 조작 버튼은 앱 테마의 일체형 제목줄에 배치한다. 빈 제목줄 영역을 끌어 창을 이동하고 더블 클릭으로 최대화·복원한다. Windows/Linux는 가장자리·모서리를 끌어 크기를 바꾸며 macOS는 네이티브 크기 조절을 유지한다. 닫기 버튼도 기존 백그라운드·트레이 또는 저장 확인·실행 정리 경로를 따른다. macOS 단축키는 Command, 다른 OS는 Ctrl로 표시한다. 대화 전송은 Command+Enter와 기존 Ctrl+Enter를 지원한다.

하단의 실행·변경 기록과 대화의 추가 관리는 하나의 전체 너비 패널에서 탭으로 전환한다. 기본은 접힘이며 대화 입력창 아래에 별도 관리 공간을 예약하지 않는다. **실행·변경 기록**은 상태 표시줄 또는 Ctrl+J, **추가 관리**는 대화 도구막대와 보기 메뉴에서 연다. 패널 높이를 조절하거나 **접기**로 닫을 수 있다. 작은 창에서는 도구막대를 한 줄로 압축하고 입력창의 실제 높이를 반영해 본문과 입력·첨부·전송 버튼의 공간을 확보한다. 긴 출력은 전체 너비에서 줄바꿈하고 스크롤한다. 관리 결과의 미리보기와 전체 원문 복사는 구분한다. 다른 화면의 관리 동작은 기존 위치에 유지한다.

부드러운 Linux 데스크톱 스타일의 메뉴바·도구막대·탭·분할 목록·상태 표시줄을 Rust로 그린다. 왼쪽 탐색은 5개 그룹에 기존 23개 화면을 유지하며, 객체 검색과 목록을 별도 패널에 표시한다. 보기 메뉴에서도 모든 화면을 열 수 있다. 오른쪽 상세 패널은 저장된 객체의 읽기 전용 조회이며 창이 좁으면 자동으로 접힌다. 대화에서는 기본으로 상세를 접어 본문을 넓히며 상단의 **상세**나 보기 메뉴에서 펼친다. 표시 선택은 화면별로 앱 세션 동안 기억한다.

설정 메뉴에서 밝은/어두운 테마를 바꾸며 선택은 앱 프로필에 저장한다. 하단 실행·변경 기록은 Ctrl+J 또는 상태 표시줄로 펼친다. Ctrl+F는 항목 검색, Ctrl+O는 작업 공간 열기, Ctrl+Q는 종료 확인이다. Ctrl+S는 체크포인트 기록이며 현재 편집 초안의 저장과 별개다. macOS에서는 공통 명령 단축키에 Command를 사용한다.

대시보드의 수치와 상태는 저장된 실제 데이터에서 읽는다. 대화에서 도구 결과는 펼쳐 볼 수 있고 입력 영역을 기록과 분리한다. 매우 낮은 창이나 펼친 하단 패널 때문에 공간이 부족하면 전체 대화 패널을 스크롤할 수 있다. 보조 작업의 ‘추가 관리’는 기존 명령·버전·확인 절차를 유지한다.

중앙 화면의 짧은 설정값은 라벨과 입력을 같은 행에 배치하고, 설명·프롬프트·본문은 넓게 편집한다. 중첩된 사각 테두리를 줄이고 제목·여백·배경 명도로 영역을 구분한다. 관련 작업 버튼은 같은 도구막대에 모으고 창이 좁으면 줄바꿈한다. 미저장 초안·비밀 값 저장·객체 버전 검증은 그대로 유지한다.

대화 입력창은 실제 입력·첨부 영역 높이에 맞춰 대화 화면 하단에 배치한다. 대화 기록은 그 위의 남는 높이를 채우므로 입력창 아래에 큰 빈 영역을 남기지 않는다. 창 크기나 첨부 목록을 바꾸면 위치를 다시 계산하며 메시지·첨부와 전송 대기 상태는 유지한다.

## 프로세스와 저장

작은 창에서는 항목 목록을 기본 접고 상단의 목록 버튼으로 연다. 넓은 창과 작은 창의 표시 선택은 화면별로 기억하며, 항목 선택이나 새 항목 작성 시 초안과 선택 객체의 소유권은 기존 규칙을 따른다. 앱 설정은 일반 설정으로 시작하며 내부 운영 레코드는 고급 관리에서 확인한다. 모델 설정은 연결 항목과 응답 설정, 접힌 고급 설정으로 구분하며 연결 시험에는 현재 저장된 프로필을 사용한다.

대화 중지와 작업 일시정지·재개는 현재 실행 상태에 맞춰 표시한다. 화면의 시각은 컴퓨터의 현지 시간과 UTC 오프셋을 함께 표시하며 저장된 UTC 시각은 바꾸지 않는다. 승인·실행 목록은 읽을 수 있는 이름과 상태로 표시하고 원래 객체 식별자는 상세 정보에 보존한다.

UI와 객체 저장은 Rust 채널과 읽기 전용 스냅샷으로 연결한다. 단일 쓰기 담당자가 변경·참조 버전·커맨드 영수증을 검증한다. 다른 작업 공간이나 절전 이전 요청 결과가 새 화면에 적용되지 않도록 열린 세대를 구분한다. 종료와 절전은 새 실행을 차단하고 소유한 작업을 정리한 뒤 체크포인트를 저장한다. 복귀 후 작업 공간을 명시적으로 다시 연다.

81개 도구의 Rust 실행·권한·결과 처리 경로를 유지한다. Nmap, Python, 셸, 사용자가 설정한 MCP 프로그램 등의 외부 도구는 필요할 때 별도 프로세스가 된다. 이 도구들을 Rust로 다시 작성한 것은 아니다. 해당 도구를 쓰려면 OS에 도구와 필요한 권한이 있어야 한다.

한글 글꼴은 OFL의 Noto Sans KR을 실행 파일에 포함했다. 출처와 라이선스는 `assets/fonts/PROVENANCE.md`, `assets/fonts/OFL.txt`에 기록했다.

Windows에서 개발·검증 중이다. macOS와 Arch Linux는 플랫폼 코드와 UI 의존성을 준비했으나 실제 호스트에서 빌드·운영 검증하기 전까지 실행 성공을 보장하지 않는다. 새 구현 검증 결과와 원본 기능 차이는 [STATUS.md](STATUS.md), [UI-PARITY.md](UI-PARITY.md), [PARITY.md](PARITY.md)를 기준으로 확인한다. 이전 Tauri의 테스트 수를 새 UI 검증 결과로 합산하지 않는다.
