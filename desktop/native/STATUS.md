## 대화·작업 삭제와 실행 상태·중지 관리

2026년 10월 14일 대화의 내역 비우기·휴지통·복원·영구 삭제, 작업의 선택적 연결 데이터 삭제, 체크박스와 일괄 작업을 구현했다. 기존 작업 보관·복원은 유지한다. 확인창은 원래 대상과 객체 버전을 고정하고 영향 범위·공유 데이터 보존·정리 가능 여부를 조회한다. 충돌과 부분 실패는 실패한 항목을 남기며 자동 재시도하지 않는다. 대화별 조회 토큰을 구분해 삭제 전의 늦은 응답과 갱신 전 스냅샷이 삭제한 메시지를 다시 표시하지 못하게 했다. 다른 대화의 초안·조회 결과는 보존한다.

실행 화면에 실제 단계·대기 이유·관찰된 마지막 진행·경과 시간·소유 실행과 저장된 도구 결과를 표시한다. 실행 또는 작업 전체를 중지할 수 있고 소유 외부 프로세스의 강제 종료는 별도 확인을 사용한다. 작업 중지는 해당 작업의 새 실행과 시간 계산을 동결하며 다른 작업은 계속 진행한다. 중지 요청 수신과 실제 프로세스·출력·호스트 요청의 정리 완료를 구분한다. Windows 도구·PTY·stdio MCP는 suspended 생성→Job 등록→재개 순서로 소유하고 Job의 남은 프로세스와 I/O까지 확인한다. 일반 작업·조회·중지 요청의 수용량을 분리해 작업 포화 중에도 중지를 전달한다.

정리 증거는 run ID·engine epoch와 함께 저장한다. 정상 종료 후 실제 retirement 보고서를 기록·체크포인트하고 다시 열어도 확인된 실행의 삭제가 가능하다. 이전 epoch의 미확인 실행은 새 빈 실행 목록만으로 성공 처리하지 않는다. 파일 이동 후 버전 충돌·취소가 생기면 원래 파일과 admission을 복원하며, 복원을 확인하지 못하면 복구 필요 상태로 남긴다. 공유 파일·다른 작업·원본 업로드는 삭제 대상에 포함하지 않는다.

## 앱 일체형 창 프레임과 플랫폼 코드 점검

2026년 10월 13일 Windows 기본 제목줄을 앱 테마의 통합 제목줄로 교체했다. 기존 메뉴 행을 40px 행으로 대체해 높이를 추가하지 않는다. 메뉴·창 버튼·이동 영역을 분리하며 최소화·최대화/복원·더블 클릭·이동과 네 변·모서리 크기 변경을 제공한다. 닫기는 기존 트레이/백그라운드 또는 저장 확인·서비스 정리 경로로 연결한다. macOS는 지원되지 않는 BeginResize 호출 대신 투명 네이티브 제목줄과 전체 콘텐츠 설정으로 네이티브 크기 변경을 유지한다. Mac 메뉴·힌트는 Command 표기를 사용하고 대화 Command+Enter를 지원하며 기존 Ctrl 전송도 유지한다.

플랫폼 점검에서 typed 파일 선택 경로를 JSON으로 옮길 때 비 UTF-8 PathBuf가 writer panic으로 이어질 수 있던 문제를 수정했다. StageFile/SaveFile은 JSON 변환 전에 scope와 UTF-8 경로를 확인해 요청 오류로 반환한다. 최근 목록 직렬화 실패는 기존 파일을 빈 내용으로 덮어쓰지 않는다. 실제 Unix 비 UTF-8 원본·목적지 불변과 같은 writer의 정상 파일 작업 회귀를 추가했으며 이 Unix 전용 시험은 Windows에서 실행되지 않았다.

최종 소스 검증은 `test-results/ccdd6e9861a242cbbf01e6a49c93878c/verification-result.json`이다. UI 82개, 네이티브 서비스 21개·호스트 51개·공통 workspace 321개를 모두 다시 실행해 통과했다. 일부 호스트/공통 시험은 겹치므로 합산하지 않는다. 통합 서비스·로컬 시험 공급자·Read 도구, Windows 23개 화면·정상 종료·두 번째 실행 검사도 통과했고 `ui-parity.json`에서 기존 168개 관리 동작과 화면 집합이 동일하다. 창 버튼·drag/menu 분리·8방향 첫 누름·잘못된 영역의 크기 조절 방지와 실제 제목줄을 쓰는 최소 창 대화/하단 패널 검사를 포함한다. 초기 `4d6a4c8165c1403691c0db41f5df943e`에서 첫 누름 크기 조절 회귀가 실패해, sizing pass의 보이지 않는 child 대신 Area 자체에서 입력을 처리하도록 수정한 뒤 재검증했다.

macOS ARM/Intel와 Linux x86_64의 잠긴 의존성 그래프 해석은 성공했다. 현재 호스트에는 Apple SDK·링커 및 Linux Rust 도구 체인이 없어 실제 Mac/Arch 컴파일·GUI 실행을 완료 처리하지 않는다. 반복 검사에서 OS 자격 증명 동시 저장 시험이 한 차례 실패했고 원인은 재현되지 않았다. 비밀 값 없는 단계·OS 오류 진단을 추가한 뒤 동시 시험 20회, 전체 검사와 실제 릴리스 서비스 검사는 통과했다. 이 관찰은 물리적 OS 출시 검증에서 추적해야 한다. OS 저장 실패는 성공으로 표시하지 않는다.

오래된 미수화 Blob 참조는 재개 후 현재 저장 세대에서 다시 조회해야 할 수 있다. 이전 UI 세대의 pin이 새 Store의 GC 등록을 계속 보장하지 않는다. 이미 입력·수화한 편집 문자열은 메모리에 보존하며 충돌 시 자동으로 최신 버전에 덮어쓰지 않는다.

## Linux 데스크톱 스타일 UI 개편

2026년 10월 13일 시안의 UI·UX에 Linux 데스크톱 앱의 표현을 더 강화했다. Rust 메뉴바·도구막대·분할 목록·작업 탭·상태 표시줄, 밝은/어두운 회색 테마와 파란 선택 표시, 작은 모서리와 직접 그린 아이콘을 사용한다. HTML 시안은 제품 실행에 포함하지 않는다.

- 기존 23개 화면을 5개 탐색 그룹으로 묶고 보기 메뉴에서도 접근한다. 객체 검색/목록을 탐색과 분리했으며 선택 상태를 표시한다.
- 우측 상세는 현재 저장된 객체의 상태·관계·버전만 조회한다. 초안을 다시 읽거나 요청의 소유권을 바꾸지 않으며 좁은 창에서 접힌다.
- 대시보드는 실제 최근 작업·승인·질문·활동을 표시한다. 시안의 예시 수치와 추정 진행률은 넣지 않았다.
- 작업의 개요/에이전트/발견 사항/증거 탭을 제공하고 기존 목표·허용 범위·탐색 노드 기능은 개요 하위 탭에 남겼다.
- 대화는 메시지와 입력 영역을 분리한다. 참조는 검색 팝업이며 도구 입력·혼합 결과·승인 기록의 전체 정보는 접힌 상세에 보존한다. 하단 패널 때문에 공간이 부족하면 전체 대화 패널 스크롤로 접근한다.
- 공통 폼의 경고/오류와 그래프 색상도 밝은/어두운 테마에 맞췄다. 테마 선택은 앱 프로필에 저장하며 작업 공간 형식을 바꾸지 않는다.

검증: `test-results/82be4547772b4da8b89e56bc5848f43b/verification-result.json`. 네이티브 UI 39개, 실제 서비스/LLM 시험 공급자/Read 도구·저장/재개 검사, 실제 Windows 23개 화면·GPU 캡처·정상 종료·두 번째 실행 요청 전달을 통과했다. 변경 없는 공통 입력 160개의 SHA-256을 대조하여 이전 서비스 19개/호스트 49개/공통 298개 회귀 근거를 재사용했다. 최신 기존 UI 근거인 `d6b2b0f1a4f841c4a2abe98191c283e0`과 (key, method, Section, mutation) 집합 168개가 일치한다. `개요`→`대시보드`는 표시 이름 변경이다. 비교 근거는 같은 폴더의 `ui-parity-result.json`에 있다.

초기 검증은 UI 39개가 통과한 뒤 Windows PowerShell의 종료 코드 조회가 실패하여 중단됐다(`4effc87fe3e24a0f8eb173db24c61a0e`). 검사기는 시작 직후 OS 프로세스 핸들을 유지하고 종료 확인 후 코드를 읽도록 수정했다. 이후 전체 검증이 통과했으며 실패한 검사는 성공 근거로 합산하지 않는다. 디버그 검증에서는 Windows 콘솔 호스트 `conhost.exe`가 관찰됐으며 별도 엔진/WebView는 없었다.

실제 위젯 회귀는 비어 있지 않은 작업 4개 탭과 대화를 440×430/680×560/1150×700 중앙 영역에서 확인한다. 첨부 5개와 실제 클릭으로 열린 참조 팝업, 입력/보내기 가시성, 초안/첨부/Snapshot 불변, 전체 도구 메타데이터와 승인 기록의 접기/펼치기를 검사한다. 이 위젯 검증을 전체 OS 입력·접근성 검증으로 확대 해석하지 않는다. macOS/Arch Linux 실제 호스트 검증은 기존의 후속 수락 항목이다.

배포 빌드의 Windows PowerShell 네이티브 stderr 경고 처리도 수정했다. Cargo를 숨긴 자식 프로세스로 실행해 stdout/stderr를 직접 파일에 기록하고 OS 종료 코드를 확인한다. 동일한 앱 소스와 수정된 검사·배포 스크립트를 함께 다시 검증한 최종 근거는 `test-results/531853503dee499abbb7ba3c4f72ba34/verification-result.json`이다. UI 39개와 실제 서비스/창/정상 종료 검사가 다시 통과했다.

선택 항목이 있는 실제 대화 캡처에서 종료 요청과 자동 조회가 겹치는 `BUSY` 표시를 추가로 발견했다. 새 조회는 서비스 Ready 상태이며 Close/Suspend/Shutdown 요청도 대기하지 않을 때만 제출한다. 수정 뒤 `46c04bed07634459accdaff78d5633a5/ui-screens/capture-results.json`의 작업·대화·밝은 대시보드 3개 실제 창이 캡처/오류 없음/정상 종료를 모두 통과했다.

밝은 GPU 화면에서 강조 글자가 흰색으로 남는 문제도 검토에서 발견했다. 일반 active 위젯의 전경색을 테마 글자색으로 맞추고 실제 선택 표시의 파랑/흰색은 유지했다. 기존 테마 시험은 실제 렌더링된 한국어 헤더·ARTEX·큰 수치를 각각 tessellate하여 그 아래 실제 표면과 4.5 이상 대비를 확인하도록 강화했다. 이러한 보완을 포함한 최종 앱 소스 검증은 `test-results/5ff4d48e31cb414889597514e8a2aa39/verification-result.json`이며 UI 39개와 실제 서비스/창/정상 종료 검사가 통과했다.
